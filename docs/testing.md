# Лабораторная работа № 4. Написание Unit тестов

Дисциплина: ИСРПО. Проект: Geometric Library.

## 1. Цели и задачи тестирования

Проверить, что библиотека вычисляет площади и периметры по формулам из [документации](README.md#math-formulas). Подобрать входные данные, вручную вычислить ожидаемые значения, автоматизировать сравнение с помощью `unittest` и зафиксировать отклонения.

## 2. Описание тестируемого продукта

Geometric Library — библиотека на Python для расчёта площади и периметра круга, квадрата, прямоугольника и треугольника. Для круга периметром считается длина окружности. Продукт предоставляет функции, сгруппированные по модулям. Их параметры и ожидаемые результаты описаны в [справочнике функций](functions.md).

## 3. Область тестирования

Проверяются восемь документированных функций. Для каждой фигуры написан отдельный класс тестов.

| Модуль | Функции | Класс тестов |
| --- | --- | --- |
| `circle.py` | `area(r)`, `perimeter(r)` | `CircleTestCase` |
| `square.py` | `area(a)`, `perimeter(a)` | `SquareTestCase` |
| `rectangle.py` | `area(a, b)`, `perimeter(a, b)` | `RectangleTestCase` |
| `triangle.py` | `area(a, h)`, `perimeter(a, b, c)` | `TriangleTestCase` |

Проверяются вычисления на числовых входах и реакция на отрицательные размеры и буквы. Ноль проверяется как граничное значение формул. Производительность и безопасность вне области проверки.

## 4. Стратегия тестирования

Используется функциональное модульное тестирование. Каждый метод `test_...` вызывает одну функцию из библиотеки. Ожидаемые значения рассчитаны заранее по формулам. Например, для прямоугольника со сторонами 5 и 10 ожидаемая площадь равна 5 × 10 = 50, а периметр равен 2 × (5 + 10) = 30.

| Функция | Входные данные и ожидаемые результаты |
| --- | --- |
| `circle.area` | `(3)` → ≈ 28.274333882308, `(0)` → 0, `(0.5)` → ≈ 0.785398163397 |
| `circle.perimeter` | `(3)` → ≈ 18.849555921539, `(0)` → 0, `(0.5)` → ≈ 3.141592653590 |
| `square.area` | `(5)` → 25, `(0)` → 0, `(2.5)` → 6.25 |
| `square.perimeter` | `(5)` → 20, `(0)` → 0, `(2.5)` → 10 |
| `rectangle.area` | `(5, 10)` → 50, `(10, 0)` → 0, `(10, 10)` → 100 |
| `rectangle.perimeter` | `(5, 10)` → 30, `(10, 0)` → 20, `(2.5, 3.5)` → 12 |
| `triangle.area` | `(6, 4)` → 12, `(6, 0)` → 0, `(2.5, 3)` → 3.75 |
| `triangle.perimeter` | `(3, 4, 5)` → 12, `(5, 5, 5)` → 15, `(2.5, 3.25, 4)` → 9.75 |

Все классы в [файле тестов](../test_geometry.py) наследуются от `unittest.TestCase`. Для точных значений используется `assertEqual`. Для ненулевых результатов с π используется `assertAlmostEqual` с округлением разности до девяти знаков после запятой.

Для каждого параметра отдельно проверяются отрицательное число и строка из одной буквы (`"a"`). Остальные аргументы в этом вызове остаются корректными. Для отрицательного размера тесты ожидают `ValueError` (число вне допустимого диапазона), для буквы — `TypeError` (неподходящий тип). Документация не задаёт поведение в этих случаях, поэтому такие исключения приняты как ожидаемое поведение при тестировании. Вызовы проверяются через `assertRaises`.

Команда запуска из корня репозитория:

```bash
python3 -B -m unittest discover -v
```

Параметр `-v` выводит результат каждого теста. Параметр `-B` отключает запись файлов кэша Python.

## 5. Критерии приёмки

- Все 50 тестов обнаруживаются и запускаются.
- Все восемь документированных функций доступны. На корректных входах функции возвращают ожидаемые числа, а на отрицательных размерах и буквах вызывают соответствующие исключения.
- Результаты запуска и обнаруженные дефекты отражены в отчёте.

## 6. Ожидаемые результаты

Если библиотека соответствует документации и принятым ожиданиям для некорректных входов, все 50 тестов получат статус `ok`. Итоговый статус запуска будет `OK`. При отклонении в отчёте указываются функция, входные данные, ожидаемое и фактическое поведение.

## 7. Актуальные результаты тестирования

Запуск выполнен на macOS с Python 3.14.0.

| Фигура | Всего | Прошли | `FAIL` | `ERROR` |
| --- | ---: | ---: | ---: | ---: |
| Круг | 10 | 8 | 2 | 0 |
| Квадрат | 10 | 7 | 3 | 0 |
| Прямоугольник | 14 | 5 | 2 | 7 |
| Треугольник | 16 | 11 | 5 | 0 |
| **Итого** | **50** | **31** | **12** | **7** |

На отрицательных размерах 11 из 13 проверок получили `FAIL`. Функции возвращали число без `ValueError`. Например, `circle.area(-3)` вернула примерно 28.2743, а `triangle.area(6, -4)` вернула −12.0. Ещё две проверки получили `ERROR` из-за отсутствия `rectangle.area`.

На буквах 10 из 13 проверок получили ожидаемый `TypeError` и прошли. Вызов `square.perimeter("a")` вернул строку `"aaaa"`: Python повторил строку четыре раза при умножении на 4. Этот тест получил `FAIL`. Ещё две проверки получили `ERROR` из-за отсутствия `rectangle.area`.

Фрагмент вывода:

```text
Ran 50 tests in 0.002s
FAILED (failures=12, errors=7)
```

Все семь ошибок выполнения имеют одну причину: документированная функция `rectangle.area` отсутствует. Python выдаёт `AttributeError` при попытке вызвать её. Эти семь случаев включают три проверки корректных аргументов и четыре проверки некорректных.

## 8. Выводы из результатов тестирования

Семь доступных функций возвращают ожидаемые числа на выбранных корректных данных. Критерии приёмки библиотеки не выполнены: `rectangle.area` отсутствует, отрицательные размеры принимаются, а периметр квадрата на буквенном входе возвращает строку. Точное поведение для некорректных аргументов нужно согласовать и описать в документации. Исходные файлы фигур в этой лабораторной не менялись.
